# Astana EMS coverage and Kazakhstan measles immunity gap

Two linked research projects in spatial and epidemiological modeling, carried out as independent study work.

- **Project A.** Optimal ambulance station placement in Astana, a covering location analysis under Kazakhstan's ten minute emergency response standard.
- **Project B.** Reported coverage versus implied susceptibility, reconstructing regional measles immunity gaps in Kazakhstan (2019–2026).

Both are one mathematical problem, allocating a limited resource across space to minimize expected harm, applied in two different domains. See section B.10 of the protocol for the connection.

## Status

This repository was created as the container for the work, with the protocol below committed first, before any analysis code. Progress is tracked in [DECISIONS.md](DECISIONS.md), and dated data provenance is tracked in [DATA_SOURCES.md](DATA_SOURCES.md).

- **Project B:** Analysis, modeling, and reporting are completed. The full pipeline runs reproducibly via `python run_pipeline.py`, generating all tables, figures, and passing automated validation tests (`pytest`). Academic reporting is compiled in `REPORT.md` (IMRaD structure with Russian summary), projection in `FORECAST.md`, and defense slides in `SLIDES.md`.
- **Project A:** Scheduled for execution following Project B completion.

## Getting the environment running

    python -m venv .venv
    source .venv/bin/activate          # on Windows: .venv\Scripts\activate
    pip install -r requirements.txt

`requirements.txt` lists pinned versions of packages in use to ensure full reproducibility (protocol section 1.3).

## Reproducing results

Once the environment is active, the complete analytical pipeline and test suite execute via:

    python run_pipeline.py

This sequentially runs all analysis modules (`src/b01`–`b10`), updates all tables in `results/tables/`, regenerates charts in `results/figures/`, and executes test suites in `tests/`.

Before reporting results, the check in protocol section 1.3 applies:

    # on Windows (cmd):
    rmdir /s /q data\processed results && python run_pipeline.py

Delete `data/processed/` and `results/`, re-run the pipeline on a clean state, and confirm that all tests pass (`5 passed`) and numbers match.

## Data

Raw data is not committed to this repository. `data/raw/` is populated locally, and every source is logged in `DATA_SOURCES.md` with its official inquiry identifiers, download date, license, and SHA-256 checksums to verify provenance. See `.gitignore` for local file exclusions.
