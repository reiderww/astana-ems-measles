# Astana EMS coverage and Kazakhstan measles immunity gap

Two linked research projects in spatial and epidemiological modeling, carried out as independent study work.

- **Project A.** Optimal ambulance station placement in Astana, a covering location analysis under Kazakhstan's ten minute emergency response standard.
- **Project B.** Reported coverage versus implied susceptibility, reconstructing regional measles immunity gaps in Kazakhstan.

Both are one mathematical problem, allocating a limited resource across space to minimize expected harm, applied in two different domains. See section B.10 of the protocol for the connection.

## Status

This repository was created as the container for the work, with the protocol below committed first, before any analysis code. Progress is tracked in [DECISIONS.md](DECISIONS.md), and dated data provenance is tracked in [DATA_SOURCES.md](DATA_SOURCES.md).

## Start here

**[PROTOCOL.md](PROTOCOL.md)** is the full research protocol: research questions, hypotheses with pre-registered thresholds, formal model specifications, data sources, the computational pipeline, sanity checks, and known risks for both projects. Read that before reading any code in this repository, since it explains why each step exists.

## Repository structure

```
astana-ems-measles/
  README.md               this file
  PROTOCOL.md              the research protocol, committed first
  DECISIONS.md            dated log of design decisions made during the work
  DATA_SOURCES.md         every data source used, with download date, license, and checksum
  LICENSE                  MIT license, applies to code
  LICENSE-text             CC BY 4.0, applies to the written reports and figures
  CITATION.cff             citation metadata
  requirements.txt        pinned Python package versions
  Makefile                 runs the full pipeline with one command (added once code exists)
  data/raw/                downloaded source data, never edited after download
  data/processed/          derived data, safe to delete and regenerate
  src/                      pipeline scripts, numbered in run order
  notebooks/                exploratory work, never the source of a reported number
  results/figures/          figures, generated by code, never edited by hand
  results/tables/           output tables, in csv
  paper/                    the two written reports and their bibliography
  tests/                    the sanity checks from the protocol, as automated tests
```

Most of these folders are empty right now, because analysis has not started. They exist from the first commit so the structure is fixed in advance, the same principle that applies to the protocol itself.

## Getting the environment running

```bash
python -m venv .venv
source .venv/bin/activate          # on Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -c "import osmnx, geopandas, networkx, pulp; print('all imports OK')"
```

`requirements.txt` lists a working starting set of package versions. Once the environment above installs cleanly, run `pip freeze > requirements.txt` to lock in the exact versions actually in use, since exact pinning is part of the reproducibility rules in the protocol (section 1.3).

## Reproducing results

Once the pipeline exists, the full analysis will run from a single command:

```bash
make all
```

Before any results are reported, the check in protocol section 1.3 applies: delete everything in `data/processed/` and `results/`, run `make all` again on a clean checkout, and confirm every number matches. If it does not, something upstream was not properly fixed.

## Data

Raw data is not committed to this repository. `data/raw/` is populated locally by download scripts in `src/`, and every source is logged in `DATA_SOURCES.md` with its exact URL, license, and a SHA-256 checksum, so the origin of every file is verifiable without bloating the repository with large geospatial files. See `.gitignore` for what stays local.
